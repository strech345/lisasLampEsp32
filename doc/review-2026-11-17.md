# Projekt-Review (Firmware + Web-UI)

_Stand: 17.11.2026 — nur Code gelesen, nichts am Gerät getestet._

## Kritisch (Bugs)

- [x] **Wecker nach Deep Sleep wird verpasst** — `src/sleep_manager.cpp:73`
  - Lampe wacht 5 Min. vor dem Alarm auf, WLAN läuft ~1 Min.
  - Danach ist der Alarm < 5 Min. entfernt → `applyEventLead` ignoriert ihn → `sleepTimeMs` bleibt `START_WIFI_AFTER_MS` (5 h).
  - Fix: Liegt ein Ereignis im Vorlauf‑Fenster → nicht schlafen.

2. **POST ohne Body bekommt nie eine Antwort** — `src/captive_portal.cpp:56`
   - Handler wird nur im Body-Callback aufgerufen; der Request-Handler ist leer.
   - Betroffen: `/factory_reset`, `/restart`, `/trigger_ntp_sync`, `/trigger_tsf_snapshot`.
   - Folge: Werkseinstellungen / Uhr-Sync aus der UI tun vermutlich nichts.
   - Fix: Bei `Content-Length: 0` den Handler im Request-Callback aufrufen.

3. **TSF-/RDS-Haken wirft Handy aus dem Hotspot** — `src/route_handlers.cpp`, `src/main.cpp:178`
   - Laufen über `STATE_CHANGE_SYSTEM_CONFIG` → `stopWifi()` + `startWifi()` + grüner Alert.
   - Fix: Eigene `StateChangeType`s ohne WLAN-Neustart (wie Warnungen / Deep Sleep).

4. **Race Conditions zwischen Web-Task und `loop()`**
   - Web-Handler laufen im `async_tcp`-Task, ändern `appConfig`/`systemSettings`, rufen `stopWifi()`/`startWifi()`, `delay()`, `ESP.restart()`.
   - Gemeinsames statisches `Preferences`-Objekt (`src/store.cpp`) wird parallel geöffnet.
   - `pendingConfig` (Debounce-Save) wird aus beiden Tasks geschrieben.
   - Fix: Web-Handler legen nur Aufträge in eine Queue / Flag; `loop()` wendet sie an.

5. **Event-Log** — `src/event_log.cpp:47`
   - JSON (bis ~18 KB, viele `malloc`) wird in `taskENTER_CRITICAL` gebaut → Interrupts lange gesperrt, `malloc` dort unzulässig.
   - `msg` wird nicht escaped → `"` in der SSID macht das JSON kaputt.
   - Fix: Einträge unter Lock kopieren, außerhalb mit ArduinoJson serialisieren.

6. **Kleinere Bugs**
   - `svelte-ui/src/App.svelte:19`: `month === 12` → Dezember ist `11`, der 24.12. wird nie gefeiert.
   - `/set_config` prüft keine Wertebereiche (Dauer 0, Helligkeit > 7, Alarm-Tag/-Stunde).
   - Fehlende Felder in `/set_config` setzen Defaults statt aktuelle Werte zu behalten.

## Sicherheit

- **Offener Hotspot ohne Login** (Standard: kein Passwort, Auth entfernt).
  - Jeder in Reichweite kann `/ota` (Firmware flashen), WLAN-Daten ändern, Factory Reset.
  - Vorschlag: Default-Passwort pro Gerät (z. B. aus MAC, Aufkleber); OTA nur mit Tastendruck am Gerät freigeben.
- **CSRF**
  - Kein Check von `Content-Type` / `Origin` / `Host` → jede Webseite im selben Netz kann POSTs (auch Multipart-OTA) auslösen.
  - Fix: Nur `application/json` annehmen, `Origin`/`Host` prüfen.
- **Body-Größe unbegrenzt** — `src/captive_portal.cpp`
  - `String` wächst bis `Content-Length` → Heap voll.
  - `_tempObject` mit `new` angelegt, Bibliothek gibt mit `free()` frei → Leak/UB bei Abbruch.
  - Fix: Limit (z. B. 4 KB), `malloc`-Puffer statt `new String`.
- **OTA ohne Prüfung** — `src/route_handlers.cpp` (`registerOtaRoute`)
  - Keine Auth, keine Größen-/Image-Prüfung; nach fehlgeschlagenem `Update.begin()` wird weitergeschrieben.
- **Passwörter im Serial-Log**
  - `serialPrint("Received /set_system_config body: " + body)` gibt Klartext aus; `DEBUG` ist immer an (`main.cpp`, `debug_utils.cpp`).
- **Factory Reset per Boot-Taste nach 1 s** — `src/button.cpp`
  - Passiert leicht aus Versehen → 5–10 s halten.
- **Firmware-Update löscht Einstellungen**
  - Ändert sich `sizeof(SystemSettings)`, wird alles inkl. WLAN-Daten zurückgesetzt (`ensureStructExists`).
  - Fix: Versionsfeld + Migration.
